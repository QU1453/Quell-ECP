# Quell-ECP 产品需求文档（PRD）

> 状态：V1.0 草案（需求已确认，待评审）
> 日期：2026-09-05
> 定位：**模拟跨境电商平台**（学习 / 演示 / 业务流程模拟用途，非真实生产交易）

---

## 1. 决策记录

| 决策点 | 结论 | 说明 |
|---|---|---|
| 平台形态 | 自营单店铺 B2C | 买家前台商城 + 运营方管理后台，第一版不做多商家入驻 |
| 一期范围 | 电商核心 | 账号 / 商品 / 购物车 / 订单 / 模拟支付 / 管理后台 |
| 跨境特征 | 二期再做 | 多币种与模拟汇率、中英双语 i18n、按国别运费、物流轨迹模拟 |
| 部署 | 自租服务器自托管 | 全部容器化（Docker Compose + Nginx），代码不出域、数据自管 |
| 模拟边界 | 无真实支付 / 无真实物流 | 支付用**本地模拟网关**，物流轨迹二期以模拟数据驱动 |

## 2. 项目背景与目标

搭建一套自有的跨境电商标的，用于：

- 跑通“商品上架 → 买家下单 → 支付 → 发货/履约 → 完成”的完整电商闭环；
- 演示与教学：前台（商城）+ 后台（运营）双端；
- 为二期演进预留清晰边界：多币种汇率、多语言、跨境物流等以模块化方式接入；
- 可在用户自己租用的服务器上一键部署（Nginx + API + PostgreSQL 三个容器起步）。

## 3. 用户与角色

| 角色 | 说明 | 主要诉求 |
|---|---|---|
| 访客（未登录） | 可浏览、搜索、看详情 | 逛得爽、信息清楚 |
| 买家（已注册登录） | 下单、支付（模拟）、查看订单 | 流程顺畅、订单可追踪 |
| 运营管理员 | 商品/分类/库存/订单/看板 | 高效管理、状态可控 |

## 4. 一期功能范围

### P0（必须，构成 MVP 闭环）

**账号与权限**
- 邮箱注册 / 登录 / 退出；JWT 鉴权；角色：`buyer` / `admin`
- 管理员账号由种子数据创建，不做自助注册

**商品与分类（运营后台）**
- 分类管理：增删改查、排序
- 商品管理：标题、描述、主图、价格、库存、上下架（软删除）

**商城前台（买家）**
- 首页 / 分类浏览 / 关键词搜索 / 商品详情
- 购物车：加购、改数量、删除、勾选结算、库存校验

**下单与模拟支付**
- 结算页填写收货地址 → 提交订单（创建即锁库存）
- 生成支付单，进入**模拟收银台**：可选择“支付成功 / 支付失败 / 取消”
- 支付成功 → 订单 `PAID`；未支付取消或超时 → 订单 `CANCELLED`，库存回补

**订单管理**
- 买家：我的订单列表 + 详情（订单号、金额、状态、地址）
- 管理员：订单列表（筛选/分页）、发货、完成、取消、退款
- 订单状态机见 PRD §5

**管理看板（基础统计）**
- 简单统计：今日/累计订单数、销售额、待发货订单数、低库存预警

### P1（一期补强，M3 前后）
- 图片上传（本地磁盘/对象存储适配器，默认本地）
- 地址簿管理（多收货地址）
- 订单多条件筛选、导出 CSV
- 前后端基础校验与错误提示完善、种子数据脚本

### P2（二期，不在本期实现）
- 多币种标价 + 模拟汇率（快照机制）
- 中英双语 i18n
- 按国家/地区计算跨境运费
- 模拟物流轨迹（揽收/清关/干线/派送等状态推进）
- 优惠券 / 促销、商品评价、搜索聚合与排序增强

## 5. 订单状态机（一期）

```
                        ┌────────────┐
      提交订单 ────────▶ │PENDING_PAYMENT│ ◀── 未支付取消/超时 ───▶ CANCELLED（回补库存）
                        └─────┬──────┘
                              │ 模拟支付成功（幂等回调）
                              ▼
                        ┌────────────┐
                        │    PAID    │── 管理员退款 ──▶ REFUNDED（回补库存）
                        └─────┬──────┘
                              │ 管理员发货（一期为“标记发货”）
                              ▼
                        ┌────────────┐
                        │  SHIPPED   │── 买家确认收货/管理员标记 ──▶ COMPLETED
                        └────────────┘
```

约束：
- 状态只能按箭头迁移，非法迁移由后端拒绝；
- 支付回调必须**幂等**：仅 `PENDING_PAYMENT` 可转 `PAID`；
- 库存：下单即扣减；`CANCELLED` / `REFUNDED` 回补；
- 支付记录（Payment）与订单解耦，可对账。

## 6. 核心业务规则（一期简版）

- 商品价格以 `分`（整数）存储，避免浮点误差；一期单一币种（默认 USD），**预留下单币种字段**，二期扩展汇率换算不改表。
- 下单校验：商品上架中 + 库存充足，否则阻止提交。
- 收货地址在下单时**快照**进订单（此后修改地址不影响历史订单）。
- 管理员的“发货”在一期为手动推进状态（无真实物流）。

## 7. 非功能需求

- 前后端分离，RESTful，统一前缀 `/api/v1`；
- 所有配置走环境变量（`.env`），密钥不入库不入仓库；
- 输入校验（API 侧统一 DTO + zod/class-validator）；
- 接口鉴权与角色守卫（买家接口与管理员接口严格隔离）；
- 容器化部署：`nginx`（静态托管+反代）+ `api`（Node）+ `postgres`；提供一键 `docker compose up`；
- 内置演示种子数据：1 个管理员、示例商品若干，开箱可演示；
- HTTPS / 域名：部署文档预留（certbot），按需启用。

## 8. MVP 验收标准

1. 用种子管理员登录后台，可新建分类与商品并上架；
2. 用买家账号在前台搜索到该商品，加入购物车；
3. 走完下单 → 模拟支付成功 → 订单变 `PAID`，库存正确扣减；
4. 后台对该订单“发货”/“完成”，买家端“我的订单”状态同步可见；
5. 买家取消未支付订单 → `CANCELLED`，库存回补；
6. 任一仓库重新部署：`docker compose up -d --build` 后全流程可复现。

## 9. 迭代计划

|---|---|---|
| **M0 基建** | Monorepo 初始化、API(prisma+pg) Hello World、Web 脚手架、docker-compose dev | 本地 `docker compose up` 起 DB+API 可连 |
| **M1 账号与商品** | 认证(JWT/角色)、分类/商品后台 CRUD、前台浏览搜索详情 | 管理员可上架商品，前台可浏览 |
| **M2 交易闭环** | 购物车、地址、下单、状态机、模拟支付、后台订单管理、我的订单 | 通过 §8 全部验收 |
| **M3 上线准备** | 种子数据、看板统计、图片上传、生产镜像 + compose + nginx + 部署文档 | 在自租服务器一键部署并演示 |
| **二期** | 多币种汇率、i18n、跨境运费与物流模拟、营销/评价等 | 另行拆分需求 |
